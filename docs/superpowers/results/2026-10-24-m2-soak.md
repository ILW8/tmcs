A bug on Windows 10 shrank the window on every restore, and each view made its windows on its first show. Both are fixed. The Debug run's one 116 ms minimize is not explained, and the check measured 28–45 ms for minimizing.
- **Idle cost (spec test 4): PASS.** On the CPU pane, tmcs used 1,352 ms of CPU a minute against Task Manager's 7,999. On Details, it used 2,713 against 10,071.
- **Icon dedup (spec test 5): PASS.** 50 copies of one exe added one image.

## Switch-time FAILs and their fixes

| Run | Segment | Transition | switch_ms | Cause |
|---|---|---|---|---|
| Debug | 1 | first show of Details | 153.24 | Details list made on its first show |
| Elevated | 1 | first show of Details | 144.9 | the same |
| Elevated | 4 | minimized → network pane | 106.71 | restore bug, plus the network pane's first show |
| Elevated | 9 | Details → minimized → CPU | 202.76 | restore bug, plus a tab switch |
| Debug | 3 | GPU → minimized | 116.07 | not explained: 10 ms in the dry run, 5.8 ms in segment 8, 27.9–37.5 ms in the check below |

The Debug run's segment 9 (95.89 ms) passed narrowly, with the same cause as the elevated run's.

**Restore bug (fixed in 41d07a5).** On Windows 10, WinForms saves the window's client size when it is minimized or maximized. On restore, it turns that back into a window size without counting the menu bar, which tmcs attaches natively. Every minimize and restore shrank the window by 20 px (780, 760, 740, …) and laid every view out twice. That happens to anyone who minimizes tmcs, not only in the soak. A restore now keeps the place and size Windows gives the window. Because of that, bounds set while the window is minimized or maximized are not applied at the restore. Nothing in tmcs sets them.

**First show (fixed in be2aa38).** WinForms makes a hidden control's window on its first show. Once the main window has shown, tmcs now makes the windows of every view, Details and the hidden panes included. Measured without churn, three runs each:

| Warm-up | First switch to Details | First switch to GPU | Cost after the window shows |
|---|---|---|---|
| None | 37–57 ms | 21–27 ms | — |
| Make the views' windows (shipped) | 15–18 ms | 18–26 ms | 34–109 ms |
| Also draw each hidden pane once off-screen | 17–18 ms | 14–17 ms | another 59–75 ms |

Drawing the panes off-screen saves under 10 ms on views far under the limit, so it was left out. The warm-up probably runs before the window first paints. If so, the window's contents appear about 40 ms later at startup. This was not measured, and startup is not under the 100 ms rule.

**Review.** An independent review approved the fixes with five Minor findings. Two tests were added for them (48e0270): a restore to a place moved while minimized, and the scenario's own restore keeping the size. Both fail without the fix.

**Test flake (f5656f7).** `SidebarTests.Up_and_down_move_the_selection` failed 1 run in 10, because WinForms adds the modifier keys held on the real keyboard to every key message. It now passes the keys to the sidebar directly.

## Owner checks

Found so far:
- **Graph lines blurrier than Task Manager's** (fidelity, 2026-10-25). Task Manager rounds each graph point to a whole pixel. tmcs drew at the exact point, so a steady value fell between two rows and showed as two lighter rows. tmcs now rounds each point as Task Manager does (look reference §3).
- **Quick F5 presses emptied the left of the graphs** (2026-10-25, fixed again 2026-10-26). Each graph kept 121 points, which is 60 s at High speed. Every refresh added one, so a burst pushed points out while they were still inside the 59-s window.
  - The first fix (810a028) let a refresh replace the newest point when the ring was full. With F5 held down, that drew a long straight line from the burst to the right edge.
  - Now a sample less than 0.4 s after the newest point's first sample folds into that point, as a mean weighted by time. A ring of 151 points then always covers the window, and a held F5 reads as one sample every 0.4 s. High speed's 0.5-s ticks never fold.
  - A grid line that falls inside a burst can sit up to 0.4 s, a few pixels, from its vertex.
  - The owner held F5 on the exe published from b3cc48c, and the graphs looked right.
- **A wide gap to the right of the CPU name** (2026-10-26). The registry name has 12 trailing spaces, and the right-aligned subtitle drew them all. Task Manager shows one, so tmcs now cuts the run to one (look reference §5).
- **The rate graphs rescale sooner than Task Manager's** (2026-10-26). tmcs changes the scale on the first sample above it, while Task Manager waits for several. The owner prefers tmcs's way, so it stays (look reference §4).
  - The time scale is unchanged: the owner prefers it to Task Manager's, which shows less time when F5 is pressed quickly.
- **Grid lines bunched during quick F5 presses** (2026-10-26). The vertical lines sat on every n-th point, so a burst of refreshes drew one every few hundred milliseconds. At the owner's request they now sit on every n-th timer sample, so they stay n intervals apart in time. While paused, a refresh counts once an interval has passed since the last counted sample. At a steady speed nothing changes (look reference §4).

## Follow-ups after milestone 2

These are parked as real but not blocking M2.

**Responsiveness**
- The first paint after a restore costs about 40 ms. Restoring and switching tabs in one step comes to 102–117 ms under churn.
- The Debug soak's one 116 ms minimize is not explained.

**Devices**
- A device that fails to read every tick also rescans every tick. The work is bounded and doesn't leak, but a back-off would save it.
- Disk letters: a volume with more than 32 extents may attribute phantom extents to disk 0. A volume with many folder mounts may lose a letter (fixed 260-character buffer).
- The sidebar builds two strings per network adapter on every paint.

**Code**
- The panes repeat much of their layout code, and `SystemGpuSource` has grown large. Both are left for a refactor.

**Tests**
- No test pins the GPU pane's engine names and percentages or the memory caption text.
- The sidebar's ink test depends on font smoothing.
- The CPU pane's cell layout can give a negative last cell on a tiny pane. Painting is safe, but `CellBounds` should clamp.

### Calls to check while trying

#### Graphs

- The x axis is time-based. The window is 59 s, which is Task Manager's 60 samples exactly at Normal. At High it shows 119 points, at Low 16. It freezes while paused. (Sidebar mini graphs and CPU pane.)
- Each graph type keeps a fixed grid step: CPU 10 samples, GPU engines 4, the rest 3. (CPU pane; the rest show from Task 15.)
- Auto-scale picks the smallest step at or above the visible maximum, from fixed lists, with a floor of 100 Kbps or 100 KB/s. (Sidebar network mini graphs; the pane scale captions show from Tasks 16 and 17.)
- The CPU grid shape for processor counts other than 32 is rows = max(1, round(sqrt(n/2))) and columns = ceil(n/rows). (CPU pane. Your PC shows the 32 case.)

#### Numbers

- Network rates use K = 1000. (Sidebar network entries.)
- Percentages and the GPU temperature round half away from zero. (Sidebar.)
- Each GPU engine graph shows the busiest node of that type, for example the max of the six Copy nodes. (Shows from Task 18.)
- The size unit is chosen before rounding, so a value a hair under a unit step shows "1024 MB" instead of "1.0 GB". (Sidebar and panes.)
- In a pair with one decimal, a zero member prints "0.0", for example "0.0/1.6 GB". Task Manager may print "0/1.6 GB". (Sidebar and panes.)
- Speed is not capped at the base speed. It follows boost above it. (CPU pane.)

#### Data

- No D3D device is ever created. The DirectX version comes from the registry's DirectX cache. (Shows from Task 18.)
- Up time comes from the system's boot time. Virtualization shows only Enabled or Disabled. (CPU pane.)
- Several drive letters on one disk are joined by a space. `Removable` follows the `RemovableMedia` flag. (Sidebar disk titles.)
- Wi-Fi signal bars are quality / 20 + 1, at most 5. (Shows from Task 17.)
- A failed process snapshot skips the whole tick, devices included. (Not directly visible.)
- If the GPU engine counters can't be opened, no GPU entry is listed at all, rather than one stuck at 0 %. (Sidebar.)
- A GPU that disappears and comes back without a device-change message stays missing until the next device-change message. (Sidebar.)

#### Sidebar

- `Show hidden adapters` isn't remembered between runs, and N counts only adapters that are present. Hidden adapters themselves are remembered, in the settings file. (Sidebar.)
- `Hide` is a check item, so it also un-hides. (Sidebar.)
- Up and Down move the selection. (Sidebar.)
- When the selected device goes, the selection moves to a same-named device of the same kind, else to the entry above, else to CPU. (Sidebar.)
- When the selected entry and the entries just above it go away in the same rescan, the selection moves to the nearest remaining entry above (for example a disk), not straight to CPU. (Sidebar.)
- The GPU entry's temperature text is black. (Sidebar.)

#### Look

- The empty 48-px band at the bottom is kept. (CPU pane.)
- Task Manager's memory fill over the graph's left border column is not reproduced, because graph data is clipped to the interior. (Sidebar memory mini graph; Memory pane from Task 15.)
- At 120 DPI, panes with stacked graphs may sit 1 px off Task Manager's spacing. (Shows from Tasks 15 to 18.)
