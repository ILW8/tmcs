### Behaviors worth a by-eye check

- The critical dialog's **Shut down** button enables only while the verification box is ticked. Tests drive the callback directly, so the real TaskDialog is unchecked. (Release only.)
- A process that exits after the menu opens is skipped silently, for single and multi selections (ruling R-L, revised). Task Manager shows its "process not found" dialog for a single row; tmcs does not.
- A multi-select end shows one confirmation and at most one error dialog for the whole batch.
- In End process tree, a descendant that already exited is skipped silently (ruling R-K).
- The End task access-denied fallback: no dialog, and the dying process's handles are closed in the background. This can block a pool thread on a synchronous pipe read. Task Manager behaves the same.
- Critical confirmation (Release): used when any selected process is critical. End process tree checks the selected roots only, not their descendants (ruling R-P).

### Calls for the owner to check (Tasks 1-5)

Each is the plan's own call unless marked. Nothing here has been confirmed by you yet.

**Ending**

- End task on a Details row goes straight to `TerminateProcess`, with no "close the windows first" pre-pass. Decided by the plan: Task Manager's pre-pass is for the Processes tab's app windows; Details rows are processes (Task 2).
- On access denied after a successful open, no dialog; handles of the dying process are closed in the background (File filter: local, disk or pipe; `DUPLICATE_CLOSE_SOURCE`). Your choice, from the reference (Task 2). Ruling R-J: the closer opens with 0x1041, and on access denied from the query retries once adding `PROCESS_QUERY_INFORMATION`.
- A multi-select end shows one plural confirmation and, on failures, one error dialog for the first dialog-worthy failure. Decided by the plan (Task 4). Ruling R-L (revised) adds that outcomes for processes that exited or whose PID was reused are skipped silently.
- End process tree ends descendants before the parent. A descendant counts only if its creation time is after its parent's, so a reused PID is never pulled in. Decided by the plan (Task 2). Ruling R-K: a descendant that is gone or changed is skipped silently; the root keeps the normal outcome.
- Critical confirmation (32443-32445) applies only to End task and End process tree, never to Set priority. Ruling R-B. In Debug it cannot detect critical processes (ruling R-M). `IsCritical` retries with `PROCESS_QUERY_INFORMATION` if the limited open or query is denied (ruling R-H).
